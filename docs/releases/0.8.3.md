# LLM Council 0.8.3

**2026-10-06: tested v5 candidate, not a publication or global-install receipt.**
Source, isolated-install and final API checks passed within the scopes below.
OpenAI `gpt-5.4` schema forwarding is restored; reasoning controls remain dropped
by Council's existing policy. The original Codex caller failure and other
verification limits remain explicit.

## Changes

- JSON, Markdown and console use `execution_status`, not `success` alone.
  Degraded output can return exit 0; neither completion nor valid JSON proves
  correct findings or substantive independent review.
- File ingestion is separate from prepared source coverage and downstream draft
  delivery. `phase_prompt_compaction` includes profile 0, original/delivered
  prompt sizes and `submitted`. Only submitted evidence cuts affect compaction
  degradation; `evidence_compacted` excludes schema-only omission. Even small
  sources can produce long drafts that require downstream compaction.
- Actual adapter starts determine `synthesis_attempts`; queued requests do not
  count. Executed retries are separate from `planned_retries`. Handled
  cancellation preserves completed evidence, while phase/provider artifact
  occurrences and persistence errors remain visible.
- CLI and library results share runtime identity. Selected native path, realpath
  and version remain distinct from `requested_model`, `adapter_resolved_model`
  and `adapter_reported_model`. Resolution may use an adapter default; it is not
  explicit selection or provider confirmation, nor is adapter reporting.
  `--models` rejects `provider:model` mappings but preserves official slash
  namespaces and colon suffixes.
- The built-in reviewer receives bounded prepared-coverage metadata as data,
  not source evidence or proof of every-phase delivery. Its added prompt boundary
  separates pipeline limitations from findings without excluding genuine
  source-backed defects in pipeline code. Security/custom schemas and public
  result schemas are unchanged; no task-intent detector or semantic regex filter is added.

An optional, non-abstract `resolve_model` adapter hook resolves the instantiated
default before capability policy runs. This backward-compatible addition does not
re-read environment variables, change defaults or override explicit models;
unknown defaults remain unknown. It restores schema forwarding for OpenAI's
`gpt-5.4` default. Council's unchanged OpenAI capability policy forwards reasoning
controls only for o-series models, covered by separate regression checks, not
`gpt-5.4`. No high-reasoning forwarding to `gpt-5.4` is claimed, and no capability
matrix change is included.

The prose-manufacturing reviewer fallback and its exclusive helpers are removed.
Schema-validation exhaustion now fails while preserving drafts, critique and
validation errors. Invalid raw synthesis is artifact-only if storage succeeds.
A synthesis exception can still fall back to an existing schema-valid JSON draft,
marked degraded. Schema validity does not establish semantic truth.

With persistence enabled, `TOOL_LOG` manifests of type `council_execution`
capture `started` and `settled` snapshots of allowlisted runtime, attempt,
occurrence, coverage and persistence-error metadata. The settled snapshot says
`ledger_finalization: not_yet_attempted`; read the terminal ledger separately.
A hard kill may leave only the start snapshot, without subsequently learned
native identity. A `running` ledger row does not prove liveness, and caller
termination does not prove every descendant exited. No heartbeat or automatic
ledger repair is added.

The original Codex caller failure is not a Council execution failure or a caller
pass. Its JSON existed 22 seconds before the caller's final response. The shipped
contract now requires waiting on the same handle and freshly reading the exact
output path after terminal completion, even after an early missing-file read or
nonzero exit. Empty stdout with `--output` is expected. A deterministic text test
checks that guidance, not model compliance. A later native Codex caller correctly
read and reported the existing result. That read-only correction passed without
a paid Council rerun; it is not a full-workflow caller re-pass and does not erase
the original failure.

In v5, OpenAI synthesis compilation records `structured_output: supported` with
`requested_model: null`, `adapter_resolved_model: gpt-5.4` and adapter-reported
`gpt-5.4-2026-03-05`. Resolution is not an explicit model choice. Reasoning controls
were dropped by existing policy; no high-reasoning forwarding is claimed.

The earlier v4 API attribution result passed independent review but used four
synthesis starts, not first-attempt success. Rejected responses and validation
diagnostics are absent from that result JSON. Confirmed option loss is not proven
to have caused its three schema-validation failures. Neither API result proves
full coverage or universal correctness.

Earlier API v3 run `5852af83-de31-496f-959f-6689e677848f` caused the hold:
coverage correctly reported 15/27, but final issues wrongly anchored pipeline
coverage gaps and draft verbosity to document line 1. Later attribution acceptance
after the narrow reviewer boundary and removal of prose-manufacturing fallback
does not erase that failure or certify every future finding.

Earlier caller runs demonstrated timeout recovery and downstream compaction even
for a 198-character source. They predate the final repair and are not v4 caller
proof. Recovered timeouts do not establish zero-failure health; successful deep
probes establish reachability only.
