# LLM Council 0.8.1 Release Candidate

## Changes

This patch repairs the boundary between a caller, Council and native CLI
providers. It does not introduce a new provider framework or change default
models. See the [portable invocation contract](../../skills/council/references/invocation-contract.md)
for shell and Python examples that also work when the skill is copied alone.

- Codex receives Council system instructions through its native instruction
  channel. Intermediate output is no longer treated as terminal completion.
- Codex and Claude require valid terminal results; partial text followed by an
  error is not success. Unsupported message shapes fail rather than lose roles.
- Attempt time includes queue wait and CLI discovery. Cleanup has a separate,
  finite allowance; cancellation must not leave an abandoned slot waiter.
- Request-owned subprocess waits preserve cancellation that races startup or
  generation completion on Python 3.10, rather than accepting a normal response.
- Native model-capacity and overload messages retain the existing transient
  retry allowance. Unsupported models still fail without transient retries.
- Neutral native usage metadata no longer masks authentication failures as
  billing failures. This fixes the error category, not the caller's credentials.
- Results add `execution_status`: completed, degraded, failed or cancelled.
  Failed execution exits 1, usage errors 2, and handled signals 130/143.
  A valid degraded result keeps exit 0, so callers must inspect its status.
- JSON result files are atomic and stdout stays empty with `--output`.
  Explicit Markdown output files remain Markdown. JSON dry runs identify
  themselves as plans with `execution_status: not_executed`.
- Missing or fully skipped reference files fail before model calls. Truncated
  input remains inspectable and makes execution degraded.
- Router provenance survives settled cancellation. A routed workflow retains
  both router and child status, without erasing the child's fallback details.
- Status distinguishes explicitly requested caller/router capabilities from
  the default local-evidence collection profile. Default pending evidence alone
  does not mean degraded execution; explicitly requested missing capabilities
  still do. Pending diagnostics remain visible in every mode, and completion
  is not evidence-quality certification. Older plans without request-intent
  metadata retain conservative pending-capability classification.
- Default-mode critique tries schema-guidance-only compaction when the full
  output-schema dump prevents a request from fitting its provider budget.
  Reference evidence is retained and the first full-schema profile is unchanged.
  The selected profile and warning expose reduced schema-specific scrutiny;
  synthesis's configured schema handling is unchanged.

## Compatibility Boundaries

Native contract verification targets Codex CLI 0.149.1 and Claude Code 2.1.288.
Other versions require a new proof before the adapters accept their behavior.
Native effort controls are model-dependent. Unsupported controls are recorded
as uncontrolled; an omitted flag does not prove that reasoning is off.

Claude and Codex CLI adapters do not provide a verified whole-generation
`max_tokens` cap. Compilation records that option as dropped instead of implying
it is enforced. Claude's per-API-request environment control can trigger internal
continuations beyond that cap, so Council does not enable it as a substitute.
API provider output-token controls are unchanged. Timeouts remain enforceable
attempt deadlines, not output-length guarantees; high-effort CLI work can require
a longer explicit timeout and a corresponding outer caller budget.

POSIX cleanup covers owned process groups, not escaped descendants, host death
or SIGKILL. Windows descendant containment is not certified. CLI flags are not
a filesystem or network sandbox. Mandatory client policy must not be bypassed;
unsupported policy/auth combinations must be reported explicitly.

Managed Claude environments are not certified for generation-only use. The
adapter rejects known local/cached managed settings but cannot detect every
remote organization policy. Certification is limited to the tested native
version, unchanged auth route and policy context. Policy/account/version changes
require fresh validation; never change credentials or endpoints to avoid policy.

Updating the Python package does not update an installed skill, plugin or a
personal slash command. Verify their versions and active paths separately.
Hermes may filter provider credentials from terminal children; a host shell's
working key does not prove access from Hermes, and is not permission to bypass
that filter.

## Release Gate

This is a candidate, not a publication record. Independent provider/runtime,
status-fix and cancellation-fix reviews are complete. Initial CI exposed two
terminal/config-sensitive test assertions and a real Python 3.10 cancellation
race; both have regression-protected corrections. Candidate 06 passed the full
local suite with current CI-like dependencies and an isolated home: 872 tests,
45 guarded native skips and 82% coverage. Those 45 native cases passed separately
with byte-identical adapter, compiler and native-test source, giving 917 distinct
passing cases. Ruff, formatting and source type checks passed. Remote Linux CI
passed on Python 3.10, 3.11 and 3.12 for candidate 05; the subsequent narrow
critique schema-guidance correction still requires matching CI and live replay.
Vulture reports 18 unchanged baseline API declarations that have
not been proved dead; they were not broadly suppressed or deleted.

The installed wheel matches the candidate package source byte-for-byte.
The remaining native caller/provider matrix is not yet complete. Publication
is held; these checks are not a substitute for the outstanding live cases.

The first installed-candidate full planning run returned `degraded`, not
`completed`: OpenAI supplied a draft, while Claude timed out and Codex timed out
then reported model capacity. All four direct short preflights passed. These
results do not establish full native-caller support. The captured capacity error
exposed the classification defect above; correcting retries does not establish
the cause of every timeout. A separately labelled Claude replay with only its
deadline raised from 119 to 300 seconds completed in 171.55 seconds with 13,380
reported output tokens, despite the original requested 4,000-token limit. Terminal
output was followed promptly by EOF and adapter return. This establishes the
output-budget limitation and a successful longer replay, not a guarantee that
300 seconds is sufficient for other tasks.

A separately labelled installed-candidate planning run with the same three
providers and models and a 300-second attempt budget subsequently completed in
611.20 seconds. All three drafts were substantive, critique and validated
synthesis completed, and there was no fallback. One Codex capacity response
recovered through the corrected transient retry policy. This is evidence for
that direct workflow, not for the original shorter budget or all native callers.

The direct whole-file code-review case also produced three substantive drafts,
critique and valid nonfallback synthesis with both seeded defects correctly
located. It exposed the default-versus-requested capability status distinction
described above: its historical result remains `degraded`, while the correction
has direct and routed regression coverage. That saved run is not silently
relabelled as a completed current-candidate run.

Actual caller diagnostics also differed from the direct terminal: default
Codex sandbox probes failed, but a separately labelled run through the caller's
normal approved escalation path passed all four providers without credential,
model or configuration changes. A sandbox-only result does not establish that
Codex cannot use Council. Hermes failed to resolve its own configured
authentication before invoking Council. Claude's caller context reached three
providers, while Codex returned capacity. These checks are not complete Council
workflows or evidence of model health.
A later actual Codex caller completed the same planning case with the pinned
Claude, Codex and OpenAI models in 544.76 seconds. All three drafts, critique and
validated synthesis were present, with no retries, errors or fallback. It used
the explicit copied candidate contract and normal approved execution path, not
an updated global plugin. Two preceding test-driver mistakes stopped before the
Council workflow and remain failed attempts, not provider failures.

Candidate 05 also completed the direct Claude/Codex/OpenRouter whole-file review
in 233.22 seconds with three substantive drafts, no retries or fallback, and both
seeded defects correctly located. Its Claude critique only narrated a file read
and reproduced the fixture instead of criticizing the drafts. This meets the
execution criteria, but does not establish useful critique quality; the narrated
tool labels are not proof that a tool ran.

An actual headless Claude caller passed all three preflights but initially ended
its session while Council was a background Bash task. The native runtime then
stopped the task; no result file was produced. A separately labelled rerun changed
only the caller lifetime instructions: foreground launch and no final response
before completed result inspection. The unchanged provider/model mix completed
in 550.04 seconds with all drafts, substantive critique and valid synthesis,
without retries, errors or fallback. The portable contract now documents this
headless lifetime requirement. This test used the copied candidate skill, not an
updated personal slash command.

Publication remains held pending final tests and the remaining live matrix.
