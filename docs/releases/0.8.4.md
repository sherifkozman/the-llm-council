# 0.8.4: Claude CLI Capability Compatibility

## Fixed

Council 0.8.3 rejected Claude Code 2.1.294 before generation because its exact
build list ended at 2.1.292. Claude admission now checks the selected executable's
advertised capabilities, not membership in a version list or range.

- `--version` records the observed identity; `--help` is checked on every call.
- Only option definitions in the Options section count. Examples and other
  sections cannot supply flags or contradict their choices.
- Required flags follow the actual command, including the auth route, optional
  system instructions and optional effort. Argument placeholders and explicit
  quoted or unquoted choice lists are checked.
- Failed probes or missing controls stop execution before task text is sent.
  Council never removes required isolation flags to make a build work.
- Probe time shares the request deadline. Existing cleanup, cancellation,
  auth selection, managed-policy checks and terminal validation remain intact.
- Doctor and compiler metadata distinguish capability advertisement from
  authentication, generation and native behavioral verification.

Current documentation, the shipped command, skill, portable invocation contract
and plugin version are updated together. Caller examples require Council 0.8.4.

## Verification

- Final implementation suite: 1,276 passed, 52 opt-in skips, 85% coverage.
- Claude contract regressions: 183 passed. Future version numbers, missing
  controls, help failures, deadlines, cancellation, fresh probing and help
  parsing boundaries are covered.
- Actual Claude Code 2.1.294: 23 contained native tests passed after final parser
  hardening. API-key and OAuth routes used dummy credentials, loopback-only
  network access, denied keychain access, and hostile hook/MCP canaries.
- Live deep probe passed on the installed 2.1.294 executable. Synthetic review
  `e55c37a9-8091-487f-923d-7b19092875ae` completed draft, critique and synthesis
  in 49.854 seconds with one synthesis attempt, no provider/validation errors,
  no retries and no fallback. It found the seeded arithmetic defect and reported
  compaction as degraded. This paid run preceded the final help-parser edge-case
  fixes; fresh native generation and doctor checks passed after those fixes.
- Ruff, formatting, mypy and diff checks passed. Vulture reports 18 unchanged
  baseline findings; this release does not claim a repository-wide dead-code cleanup.
- Independent review closed all three identified parser edge cases after
  reproducing them and checking their fixes. Council did not approve its own fix.

## Boundaries

Help establishes advertised syntax, not future isolation semantics, accepted
settings-JSON keys, authentication or successful model output. Native checks
prove the tested build and routes only. Per-call checks do not make executable
replacement between probing and dispatch atomic. Flags are not an OS sandbox.

Codex's exact-version admission remains unchanged. Issue #64 is only partially
addressed and must remain open for Codex. No default models, credentials, native
installations or personal configuration are changed. Hermes remains unverified.
Generated severity and robustness opinions are not independently certified.

Published-artifact, clean local installation and post-install receipts are added
to the GitHub release after those operations succeed. Updating the Python tool
does not itself upgrade a cached client plugin.
