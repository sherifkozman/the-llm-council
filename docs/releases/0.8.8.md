# 0.8.8 Codex 0.166.0 compatibility

Council 0.8.7 rejected Codex CLI 0.166.0 because the maintained compatibility
record did not yet include that build. This release includes the qualified
record update. Council itself still fetches the separately maintained record,
so qualifying a future compatible build does not require another package release.

The record covers the six official npm platform builds for macOS, Linux and
Windows on ARM64 and x86-64. The macOS ARM64 entry also covers a common private
runtime copy for Homebrew and npm. Its 40 files have identical hashes and
executable classifications in both distributions. Distribution-specific
metadata and a Homebrew-only helper are absent from the private copy. Intel
Homebrew is not separately qualified for this build.

No provider adapter, runtime dependency, saved configuration, authentication
boundary, tool control or subprocess permission changed. Unknown builds and
contexts still fail closed.

- [Native qualification run 41013416989](https://github.com/sherifkozman/the-llm-council/actions/runs/41013416989)
  passed all six platforms using synthetic credentials and response endpoints.
  All six npm registry signatures verified.
- The exact common macOS ARM64 copy passed 18 synthetic cases under an
  OS-enforced loopback-only network policy. Four live ChatGPT requests using
  `gpt-6.1-sol` passed for default/high reasoning and text/JSON schema output.
  The installed binary's OpenAI Developer ID signature verified.
- All ten existing build entries and the record expiration were preserved.
  The actual record parser and unambiguous inventory selection passed for all
  168 contexts; 111 record and admission tests passed.
- A Council review produced three substantive approving drafts, but synthesis
  did not finish within five minutes. An independent review approved the record;
  no completed Council quorum is claimed.
- On 2026-10-29, OSV returned no matches for public npm `@openai/codex` 0.166.0.
  CVE Now was unavailable. This does not cover all dependencies or runtimes.

The weekly provider monitor is read-only. New builds and contexts need
qualification and a record update before use. The current record expires on
2026-11-28 and is limited to 256 KiB. A desktop sandbox that blocks network
access cannot fetch the record; Council needs the permitted outside-sandbox path.

One separate large synthetic Vertex synthesis returned 504 DEADLINE_EXCEEDED
after its short health probe succeeded. This release does not claim to resolve
that provider failure or prove real provider access on every platform.
