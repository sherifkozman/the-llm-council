# LLM Council 0.8.2

This patch addresses evidence loss and incomplete-response reporting in large
reviews. It does not diagnose the tester's OpenRouter model as unhealthy: the
original HTTP response was not captured, so its upstream empty-output cause is
unknown. Council now reports the facts returned by a failed response.

## Review Evidence

Every synthesis compaction profile retains draft findings. Full source context
can be omitted for budget, but draft evidence cannot be omitted with it. If no
evidence-bearing profile fits, Council skips that synthesis request rather than
send an oversized or evidence-free prompt. Existing validated-draft fallback is
still available and explicitly degraded.

Critique may still be skipped when its prompt cannot fit. Inspect
`execution_status`, `execution_plan.phase_prompt_compaction`, and warnings;
`success: true` alone does not establish a complete review. A mixed-provider run
cannot restore whole-file source context after a peer has used chunked drafts.

Reviewer output claiming `scope.files_reviewed: 0` is rejected when file blocks
were supplied. A conservative evidence fallback needs actual findings; an empty
fallback is not an approval.

## Provider Diagnostics

Blank or whitespace-only generation fails as `empty_response`. Diagnostics expose
provider, phase, sanitized finish reason, and whether tool calls were present.
They do not expose raw reasoning or tool arguments. Tool calls are not executed.
JSON present only in OpenRouter reasoning fields is not promoted to final answer
text, even when structured output was requested. Version-error diagnostics use
the selected authentication redaction context without changing the child
process environment; suppressed exception context stays suppressed.
Empty output is not retried as a transient transport error. A surviving peer can
still yield a degraded result, but all-empty drafts stop the run.

An explicit `--max-tokens` now also controls chunked drafts. Previously that
override was silently capped at 900 tokens. `finish_reason=length` means output
hit a generation limit; it does not establish model instability. For a
reasoning-heavy review, a caller can deliberately use `--runtime-profile default
--timeout 300 --max-tokens 8000`. This increases the allowed work and potential
cost, not the guarantee of a successful response. Default chunk caps remain
unchanged; inspect the per-phase effective budgets.

A deep doctor probe must return text to pass. It proves that the selected
executable/authentication/model path can answer a small request; it does not
certify a large review, provider quorum, or evidence coverage.

## Limits and Callers

Native support is an explicit tested allowlist: Codex 0.149.1 and 0.153.3;
Claude Code 2.1.288, 2.1.289, 2.1.290, 2.1.291, and 2.1.292. This repairs the
reported installed-version failures, not arbitrary future auto-update
compatibility. An untested executable fails with its path and observed version.
#64 remains open for future-version compatibility policy; this patch does not
implement a permissive version range or an unverified-version override.
Do not edit installed version constants or assume that matching help flags prove
tool isolation. New entries require native request/response contract tests.

The reasoning mapping reported in #58 shipped in 0.8.1 and remains in place:
Codex and Claude high/low effort is sent through their native controls. Compiler
metadata lists the verified versions; the legacy `requires_cli_version` field
is the baseline, not the complete supported set.

`--timeout` is a per-provider-attempt budget, including queue wait and startup,
from 10 to 3600 seconds. The default remains 120. Bounded runtime can impose
lower phase budgets; use the default runtime for a deliberately longer attempt.
Retries, chunked drafts, critique, synthesis, and cleanup can make total elapsed
time longer. The calling tool must wait for the process and read the result file.

File caps remain 50,000 characters per file and 200,000 total. Existing
`execution_plan.context_preparation.files` records retained and original sizes;
`degradation_report.context_warnings` now provides structured truncation notices
as well. Truncation is a context limitation, not a provider failure. Smaller,
focused file sets are preferable to claiming a full review from truncated input.

The shipped plugin, command, and portable skill require 0.8.2 for these fixes.
Personal client settings and credentials are not changed by this release.
Hermes-specific runtime verification remains deferred.

## Verification Boundary

Two large live checks used four public synthetic Python fixtures totaling 53,001
source characters, without a Git repository:

| Run | Providers | Observed result |

| `e565222a-ccb5-4d48-a843-da221356ec13` | OpenRouter, Vertex AI, OpenAI | Bounded runtime: Vertex/OpenAI drafts, critique and valid synthesis found both seeded bugs. OpenRouter hit an output-length limit on a 900-token chunk and was explicitly reported as failed. Degraded, not full-provider success. |
| `663d0a0b-47cf-4ed4-8649-e78706b9c40a` | Codex CLI, Claude CLI, OpenRouter | Default runtime, timeout 300, max-tokens 8000: all three substantive drafts, valid nonfallback synthesis, both seeded bugs. Critique was skipped for budget; status remained degraded. Codex recovered after one deadline retry. |

The second run exercises the reported no-critique/large-whole-file failure:
synthesis retained draft evidence instead of accepting an empty zero-files
verdict. These are execution/evidence checks, not a claim that every model finding
is correct. The result included an unsupported overdraft-code detail, so human
assessment remains necessary.

Deep probes returned text for OpenRouter, OpenAI, Vertex AI, Codex CLI and Claude
CLI. One earlier Claude probe waited behind an unrelated Council run and timed
out; a later probe passed without bypassing locks or changing authentication.

The final installed candidate also completed focused API run
`d33c53af-6a17-4de2-89f7-59cacc0a32e9` against one synthetic file with OpenRouter,
Vertex AI and OpenAI. OpenRouter and OpenAI produced substantive findings;
OpenRouter supplied critique and valid nonfallback synthesis identifying the
seeded subtraction defect. There were no provider errors or retries. Vertex
returned nonempty but unfinished schema-planning text, not a usable review.
Therefore this run proves execution completion, not three substantive independent
reviews. `completed` does not certify the quality of a nonempty draft.

Final local verification: 1,058 tests passed with 83% coverage; 45 opt-in native
cases were skipped in that run and passed in a separate 144-test native run.
Ruff lint/format, mypy (44 source files), lockfile validation and diff checks
passed. Vulture reports 18 unchanged protocol/registry candidates that were not
established as dead code; obsolete reasoning-recovery helpers were removed.
Independent source review approved the final patch after redaction and
final-answer-channel regressions were fixed.
