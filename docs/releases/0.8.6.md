# 0.8.6 Provider Compatibility Maintenance

Date: 2026-10-28. This record describes the release candidate. Publication and
artifact receipts must be verified separately. It does not claim that local
Council installations or provider credentials were changed.

## Claude CLI

Some Claude Code builds returned exit zero with truncated `--help` output when
captured through a pipe. Council could then report required controls as missing
and reject the provider before generation. Help capture now uses a bounded
terminal stream, with a bounded pipe fallback when a terminal cannot be opened.
It retains deadline and process cleanup handling. The required permission choices
must be explicitly advertised; missing or incomplete definitions fail closed.

Help describes syntax, not authentication, isolation semantics, actual generation,
or all future versions. No tool, permission, managed-policy, authentication,
terminal-response validation or cancellation requirement is intentionally
weakened. The help check is not an OS sandbox or an atomic executable binding.

## Dependency requirements

The `gemini`, `google` and `vertex` extras require `google-genai>=1.52.0`.
Council uses retry options and high thinking-level configuration that earlier
releases do not all support. In local testing, 1.51.0 failed Gemini and Vertex
request serialization on Python 3.10; 1.52.0 passed the tested wire paths.

The base package requires `pydantic>=2.10.6`, `pyyaml>=6.0.1`, and
`typer>=0.20.1`. Previously declared minimums failed local minimum-resolution
installation or CLI tests. The lockfile requirement metadata is synchronized;
its selected third-party package versions are unchanged. Resolvers may select
newer compatible versions, and constraints from other packages may prevent an
upgrade.

## Verification and limits

- The versioned candidate passed full suites against minimum-direct `[all,dev]`
  environments on macOS/Python 3.10, 3.11 and 3.12: 1,309 passed and 52 skipped
  on each. An initial concurrent run had a retry-timeout test failure on 3.11
  and a subprocess startup-timeout failure on 3.12; both tests passed in focused
  checks and both full suites passed when run sequentially. The skips are
  untested cases.
- Claude Code 2.1.312 passed 23 contained native tests using a loopback mock,
  synthetic credentials and hostile hook/MCP canaries. These are tests of that
  build and environment, not proof of live-provider readiness.
- Synthetic in-memory HTTP tests exercise selected OpenAI, Anthropic,
  OpenRouter, Gemini and Vertex request and response paths with real SDKs.
  They do not certify all models, auth routes, platforms or future releases.
- Independent local review identified and checked corrections to the help
  capture and regression tests. A material Council code review with three
  complete independent drafts was unavailable; no Council approval is claimed.
- A 2026-10-28 verified-TLS OSV check returned no matches for the selected
  Google GenAI, Pydantic, PyYAML and Typer floor and locked versions recorded
  in the task evidence. CVE Now was unavailable. These are limited checks, not
  a security clearance for the complete dependency tree or runtimes.

## Codex and other remaining work

Codex CLI automatic qualification is not implemented in this release. Council
continues to admit only the existing verified Codex versions: 0.149.1, 0.153.3
and 0.160.1. A newer version may require another Council release. The planned
no-release route remains open because the qualification and production isolation
boundary and executable binding have not been established. No version gate was
relaxed.

The full cross-platform dependency/native matrix and native Gemini CLI checks
remain unverified. The separate local Codex scheduled monitor can identify public
release changes; it reports unavailable behavioral checks as untested and does
not itself qualify a native CLI.
