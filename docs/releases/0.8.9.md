# 0.8.9 Provider SDK compatibility and dependency refresh

This release updates the Anthropic adapters for current SDK request signatures
and API constraints. Direct Anthropic and Vertex Anthropic dependencies now have
a minimum SDK version of 0.87.0. The adapters adapt structured-output arguments
to the installed SDK, use its beta messages interface where required, and omit
temperature when reasoning or the selected model/API does not support it.
Request compilation records when it drops an incompatible option. Synthetic
wire tests cover direct Anthropic and Vertex request bodies, including reasoning
and structured output.

The Gemini API adapter keeps `v1beta` as its default API version across Google
GenAI SDK versions. `GOOGLE_GENAI_API_VERSION` can still select an explicit API
version, including the `beta` alias. The Vertex Gemini path is unchanged.

The lockfile refreshes dependencies to the latest compatible versions for the
supported Python range. It includes Anthropic SDK 2.6.0 and Google GenAI 2.33.0
for Python 3.10 and 3.0.0 for newer supported Python versions. The package
minimum remains Python 3.10; this release does not change the native CLI
admission policy.

## Verification and limits

- Hosted synthetic compatibility matrix: 18 jobs passed across Linux, macOS and
  Windows; Python 3.10–3.12; minimum and latest dependency resolutions; and all
  seven installation sets. Required SDK wire and parser tests ran and did not
  skip. This does not prove live provider behavior or native CLI compatibility.
- The exact-lock all-extras check passed on Ubuntu 24.04 with Python 3.12.16:
  19 synthetic tests passed, including all required wire-test identities and the
  parser test. Other exact-lock OS/Python combinations were not verified by this check.
- Full CI run [42433325287](https://github.com/sherifkozman/the-llm-council/actions/runs/42433325287)
  passed on Python 3.10–3.12. The Python 3.11 job reported 1,539 passed and
  52 skipped tests. Skips remain unverified; this run did not qualify native
  provider CLIs or make live provider requests.
- A synthetic Pydantic request validation-and-serialization microbenchmark on
  Ubuntu with Python 3.12.16 measured median times of 7,877.7 ns for Pydantic
  2.12.5 / pydantic-core 2.41.5 and 6,115.1 ns for Pydantic 2.14.3 /
  pydantic-core 2.50.4 across five alternating samples. Input and serialized
  output matched. This narrow benchmark is not evidence of end-to-end Council
  performance or a general workload speedup.
- Public-package advisory lookups returned no indexed matches for the checked
  package/version pairs on 2026-11-07. This is not complete dependency-tree or
  runtime security clearance.

No live provider qualification, native CLI qualification, completed Council
review quorum, synthesis fix, or Codex 0.167 qualification is claimed here.
