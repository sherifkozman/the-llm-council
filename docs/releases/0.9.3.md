# Council 0.9.3

## Vertex review reliability

Vertex AI waits up to five seconds per attempt for its local provider slot.
`vertex` and `vertex-ai` use the same slot. If the slot limit expires first,
Council reports `provider_busy`, records that generation did not start, and
continues with available peers. A request deadline that expires before
generation is still a timeout. Inspect `execution_status`, `provider_errors`
and `execution_plan.provider_attempts` to distinguish these outcomes.

Queue wait, generation and retry backoff share the Vertex request deadline.
A retry needs at least five seconds left when generation begins. The reasoning
level, model defaults and output token limits are unchanged. When an empty
response reaches its token limit, Council rejects the draft and includes the
reasoning and visible output counts if provider usage is verified. A small
readiness probe does not establish reliability on long Carbon or Argon reviews.

## Codex shared ChatGPT login

Council qualifies the exact Codex 0.170.0 macOS ARM and Linux x86-64
inventories in the [shared-login feed](../../compatibility/codex-shared-v1.json).
Both platforms admit `gpt-6.1-sol`. macOS ARM also admits `gpt-5.6-sol`. The
tested contexts support default or high reasoning and text or JSON-schema
output. Both the updated Council package and the trusted feed are required.

The macOS ARM Homebrew and npm inventories match. The macOS ARM and Linux
x86-64 entries were verified against synthetic loopback tests using isolated
homes and restricted network access. The tests used synthetic credentials.
Run a live generation canary on each host before deploying the new runtime.
