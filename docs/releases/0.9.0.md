# 0.9.0 Release candidate: provider reliability and accounting

This candidate improves provider usage reporting, cache telemetry, synthesis
handling and degraded-run reporting. Planner and security prompts distinguish
supplied evidence from proposals. A timeout before a provider starts is reported
as local queue or scheduling wait, rather than as an upstream timeout.

## Cost-reporting migration

`cost_estimate.estimated_cost_usd` is now nullable and is currently `null` for
new runs: provider token usage does not establish the complete bill. Consumers
must handle `null` before arithmetic or formatting. When sufficient verified
usage and configured rates exist, `reported_usage_estimate_usd` is a separate
flat-rate approximation, not a provider invoice. Missing usage, unpriced
providers, retries and cache billing can make it incomplete. Saved historical
results retain their recorded values.

Automatic provider prompt caching remains an explicit, default-off option.
Cache read and write counters reflect only valid provider-reported data; a
reported zero is distinct from missing data. Unsupported providers drop the
explicit option. A reported cache read does not by itself establish savings or
the total charge.

## Gemini 4 Hydrogen

Council supports schema-constrained Hydrogen responses through Gemini and
Vertex. With reasoning enabled and no explicit limit, it allows up to 16,000
output tokens per phase, including thinking tokens. This higher per-call limit
can increase cost and latency; actual usage depends on the model. Use
`--max-tokens` to set a per-call cap or `--runtime-profile bounded` to use the
bounded phase limits. Explicit per-phase limits in `OrchestratorConfig` are also
preserved.
A cap can truncate output and degrade the run, so check `execution_status` and
the provider finish reasons rather than relying on `success` alone.

A synthetic Vertex critic run and planner run completed using Hydrogen. A
clean critic case initially exhausted the earlier 4,000-token draft limit and
completed on one repeat after the allowance change. These single-provider tests
are not a reliability, accuracy or cost benchmark. Direct Gemini API execution,
other modes and Hydrogen cache savings were not established by these tests.

## Native Codex login

For qualified ChatGPT-authenticated Codex builds, Council uses the selected
native `CODEX_HOME` rather than copying refreshable credentials. It constrains
the request to the workspace selected at startup and fixes the child process's
refresh endpoint to OpenAI. The native current login is used within that
workspace; a same-workspace user change can select another user. Native global
`AGENTS.md` instructions are included. Council ignores user configuration for
generation to avoid inherited MCP servers and tools, and does not explicitly
suppress native rules. Full parity with native configuration and policy is not
established. ChatGPT CLI raw output and error details are withheld from response
metadata and errors because a credential can rotate after initial redaction.

Shared-login admission requires an exact build and request context in the new
separate shared-login compatibility feed. The legacy feed remains unchanged for
existing Council installations and API-key authentication. Initially qualified
records cover the tested macOS ARM builds of Codex 0.167.0 and 0.167.2; other
builds fail closed unless separately qualified and added. The candidate feed
must be published at its fixed trusted origin before this path can be used.
The candidate record expires on 2026-11-28 and must be refreshed before then;
an expired or unavailable record makes shared-login admission fail closed.

## Evidence and limits

A source-candidate check on macOS ARM used the existing ChatGPT login and returned
the expected response; it used the local candidate record because the new feed
was not yet published. The normal Codex CLI remained logged in afterward.
Synthetic native tests covered selected-home resolution, model request formats,
tool rejection, workspace mismatch, fixed refresh destination, and one
simultaneous-refresh rejection scenario. These checks do not prove all token
refresh schedules, managed-policy behavior, or other platforms.

Selected provider SDK, CLI and accounting tests passed with the updated locked
OpenAI, Anthropic, Typer and Google Auth versions on Python 3.10 and 3.12.
Python 3.10 is retained for compatibility but reached [upstream end of life](https://devguide.python.org/versions/)
on 2026-10-01; use a supported Python release for security updates. Native CLI
qualification CI requires Node.js 26.13.1 or newer in the 26.x series, which
includes the [November 2026 security fixes](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases).
Provider and planner smoke checks are samples, not reliability or accuracy
benchmarks. One completed three-provider planner sample contained a malformed
dependency entry despite passing schema validation; review plan details before
using them. Vertex queue contention and provider timeouts can still degrade a
run; `success` alone does not establish a completed quorum. Final CI, platform
qualification, artifact and installed-package checks are release prerequisites.
